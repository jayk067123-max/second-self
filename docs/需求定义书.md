## 1. 一句话定位

> **把散落在七个群和一堆截图里的时间重新收拢：它先替你找出冲突，再把一天重新排开，每一步都能反悔。**

产品名「第二自我」，视频标题用「撞不撞」做钩子。

## 2. 红线（v1.1 修订版 · 全队不可协商）

**红线 1 · 判定与提议分离**
确定性代码负责"判 + 存"，大模型只负责"读 + 提议"。冲突判定、方案校验、快照回滚全在 `src/domain/`，断网可用。

**红线 2 · AI 只在三个明确动作后面**（v1.1：原为两个，新增「解析这张图」）
`解析这段话` / `解析这张图` / `生成重排方案`。**绝不提供自由聊天入口**，不做"跟 AI 聊着聊着就排好了"。

**红线 3 · 数据入口只有三条**（v1.1：原为两条，新增截图路径）
粘贴文本 / 截图（图片）/ 手动新增。无 OAuth、无账号体系、无云同步，数据全在浏览器本地。

> 红线的任何改动需「选题官 + 主 Bot」双签。**v1.1 这两处修订已按主管chief 2026-10-18 开工指令落笔（截图→任务、完整性校验两条已在代码里落地），双签记录待补。**

## 3. 用户与故事

目标用户：福州某本科院校大二学生（6 门课 / 社团部长 / 备竞赛 / 周末兼职），信息源 7 个入口，历次日历 App 均弃用。

1. **录入**：把一段乱糟糟的群通知**或一张课表截图**丢进去，它变成能看懂、能改的时间块，不漏行。
2. **决策**：系统主动把冲突画出来（重叠、来不及、当天超载、DDL 前置不足），并给 2–3 套重排方案对比"挪了什么、代价是什么"。
3. **敢用**：接受方案后能一键回滚；重传课表时旧数据被干净替换，而不是叠加成一堆重复项。

## 4. 功能需求（FR）

状态口径：**已落盘** = 对应源文件在仓库里，本岗已核文件存在；**未验收** = 未由本岗实跑；**未落盘** = 只在本需求书里存在。**任何"已落盘"都不等于"已通过"。**

| 编号 | 需求 | 验收标准（可判定的） | 优先级 | 状态 |
|---|---|---|---|---|
| FR-01 | 粘贴文本 → 任务结构化 | 粘贴一段真通知，产出含 `title/date/start/end/location/priority` 的任务卡；不确定字段 `needsReview=true` 并黄框；有**人工修正表格**可改 | P0 | 已落盘（`api/ai/parse-tasks`、`TaskCorrectionTable`），未验收 |
| FR-02 | 截图 → 任务结构化 | 客户端先压缩再上传；模型读出多行课表后逐行成卡；**图片路径不显示覆盖率**（没有可信原文可比对） | P0 | 已落盘（`api/ai/parse-image`、`ImageIntake`），未验收 |
| FR-03 | 完整性校验 | 服务端用原文**逐行重算**：每行只有三种归属（已覆盖 / 日期上下文 / 没看懂待确认），不采信模型自述；`uncovered` 必须以「没看懂，请你确认」呈现，用户可逐行补成任务或显式忽略 | P0 | 已落盘（`domain/completeness.ts`、`UncoveredNotice`），未验收 |
| FR-04 | 手动新增任务 | 一个表单 10 秒加一条（时长、截止、优先级） | P0 | 已落盘（`ManualAddForm`） |
| FR-05 | 冲突检测（本地纯函数） | 4 类：时间重叠、缓冲/通勤不足、单日超载、DDL 前置不足；区间半开 `[a,b)`；`now` 注入；同输入三次一致；`severity` + `evidence` 可解释 | P0 | 已落盘（`domain/conflicts.ts`），未验收 |
| FR-06 | 冲突可视化 | 周视图红色重叠带 + 冲突卡片列表，点卡片定位时间轴 | P0 | 已落盘（`ConflictPanel`、`DayTimeline`），未验收 |
| FR-07 | 重排方案生成 | LLM 只出时间块 JSON；本地校验不通过即丢弃（不呈现非法方案）；未消除的冲突不许隐藏 | P0 | 已落盘（`api/ai/replan`、`domain/reflow.ts`），未验收 |
| FR-08 | 方案并排对比 + 接受 | 2 套并排，高亮"挪了哪几条、牺牲什么"；接受前快照入栈 | P0 | 已落盘（`ReplanPanel`、`domain/snapshot.ts`） |
| FR-09 | 回滚 | 应用后整体替换回上一版，可多步撤销 | P0 | 已落盘，未验收 |
| FR-10 | 今日视图 + 几何分身 | 今日清单 + 进度环/三态/呼吸动效；不做 3D、不做立绘 | P0 | 已落盘（`AvatarCard`、`domain/avatar.ts`） |
| FR-11 | 本地持久化 | 刷新不丢；JSON 导出能被自己导入回来；导入前留快照 | P0 | 已落盘（`data/local-adapter.ts`、`DataPortability`） |
| FR-12 | **重传课表自动覆盖** | 同一来源重传时，旧任务按来源整体替换而非追加；覆盖前留快照可回滚；界面明确告知"覆盖了 N 条" | P0 | **未落盘**（口径见 TBD-2） |
| FR-13 | **缺信息主动追问** | 把 `needsReview` + `uncovered` 聚成**最多 3 条结构化提问**（选项/填空），答完即改字段并清除该条 needsReview；**不进聊天形态** | P0 | **未落盘**（口径见 TBD-3） |
| FR-14 | 演示数据一键载入 | 载入"乱糟糟一周"种子，可一键清空，与真实数据互不污染 | P0 | 已落盘（`data/seed.ts`、`shared/samples.ts`） |
| FR-15 | 周/日视图切换、单条拖拽微调、`.ics` 导出、暗色主题 | —— | P1 | 未落盘 |
| FR-16 | 每日播报（3 条，带数字锚点） | 文案必须含真实数字（几条冲突、空出几分钟） | P1 | 未落盘 |

**P0 收口口径**：10-24 前端定型前，FR-12 / FR-13 若仍打不通，**退回 P1 并写进分镜的"不做"说明**，主线闭环（录入→完整性→冲突→重排→接受→回滚）不因它们延期。

## 5. 非功能需求（NFR）

| 编号 | 需求 | 判定方式 |
|---|---|---|
| NFR-01 | **零密钥可跑**：无 `LLM_API_KEY` 自动走 demo provider，打印 `[demo mode]`，全链路照常 | 断网/无 key 实跑一遍 |
| NFR-02 | 10 分钟复现：clone → install → 配 env → 启动 → 走完主流程 | 换机实测并记录时间 |
| NFR-03 | 无外部服务依赖：无数据库、无第三方注册 | `package.json` 依赖可核 |
| NFR-04 | 错误可见：禁止白屏、禁止静默吞错、禁止空数据冒充成功 | 故意注入坏 JSON，看修复入口是否出现 |
| NFR-05 | 性能：首屏 < 1.5s，时间轴与分身 60fps，尊重 `prefers-reduced-motion` | 演示机型实测 |
| NFR-06 | 隐私：任务数据不出本机；图片与密钥不进仓库 | `git ls-files` 抽查 + `.gitignore` |
| NFR-07 | 演示素材只用脱敏样例，真实姓名/学号/班号一律替换 | 截图与视频逐帧核对 |

## 6. 明确不做（v1.1）

账号体系 / 登录 / 云同步 / 多设备、第三方日历 OAuth、自由聊天式交互、3D 与人物立绘、语音交互、多人协作与分享广场、原生 App（只做响应式 Web）、拖拽式甘特图自研引擎、月视图与学期视图、自动推送提醒、番茄钟打卡类泛效率功能。
**新增（v1.1）**：不做**多图批量合并**、不做**手写体专项优化**、不做**追问的自由对话化**。
