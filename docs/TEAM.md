# 团队分工

| 角色 | 负责 | 对应评分维度 |
|---|---|---|
| 选题官 | 候选选题、痛点定义、MVP 范围裁剪、高光镜头 | 解题有效性与实用价值 25% |
| 全栈手 | 架构约束、模块分层、代码实现 | 工程质量与架构设计 15% |
| Prompt官 | 意图卡模板、Prompt 链归档、上下文与约束策略、防"拼接"论证 | 过程可复现 25% + 意图控制 20% |
| 交付官 | **唯一** git 提交/推送执行人、提交粒度守门、快照索引核对、最终提交物清单 | 过程可复现 25% 中的仓库与演进记录 |
| 文档官 | README 10 分钟复现指南、≤30 页 PDF 技术文档 | 可复现性论证 + 工程表达 |
| 映像官 | 视觉规范、交互走查、5-8 分钟演示视频分镜（含 ≥2 分钟 AI 协同录屏） | 用户体验与产品精细度 15% |
| 评委 | 按官方五维标准对抗式自检、扣分点清单、答辩问答 | 全维度（守门） |

## 工作流

1. **选题官** 出候选 → **人类拍板**
2. **Prompt官** 出意图卡 → **全栈手** 按架构实现
3. **全栈手** 通知 **交付官** → 交付官检查 diff 后提交（一次一模块）
4. **Prompt官** 归档本轮 Prompt 快照，交付官核对索引
5. **映像官 / 文档官** 并行补 UX 与文档
6. **评委** 阶段性打分，致命项回炉

## 纪律

- 提交信息格式：`feat: <模块名> - <这一轮引导AI做了什么>`
- 分支：`main` 保持可运行，实验在 `feat/<模块名>`
- 任何真实密钥、`.env`、大体积原始录屏素材不得入库
