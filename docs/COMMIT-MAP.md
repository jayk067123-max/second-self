## 三、已知不完美之处（如实标注，不做美化）

**1. `e7bc43c` 是三个模块合一提交。**
它一次性提交了 `avatar`（数字分身）、`conflicts`（冲突检测）、`planner`（重排方案）三个模块及其单测，共 7 文件 640 行。赛题要求"一次提交对应一个功能模块或一轮 AI 协同"，这条严格来说不达标。**保留不改写**（历史冻结令 + 改写会破坏 INDEX 引用链），作为代价记录在此。

**2. `e7bc43c` 同时补了 `cf1b37a` 的依赖缺口。**
`cf1b37a`（四层目录与领域契约占位骨架）里 `src/domain/index.ts` 已经写了 `export * from "./avatar"`，但 `avatar.ts` 是在该提交落盘窗口期才创建的、没被卷入，导致那条提交**单独 checkout 时 typecheck 会挂**。`e7bc43c` 用"往前追加一条"的方式补上，而不是 `amend` / `reset`（符合历史冻结令）。所以评委看到相邻两条"一挂一绿"是正常的，不是 CI 不稳。

**3. `2a002a6` 曾含本机绝对路径，已由 `c81e875` 修正，且决定不改写。**
路径不含敏感信息（手机号/邮箱/身份证/token 均零命中）；改写会破坏演进链真实性、并让 INDEX 引用悬空；而且"出现 → 修复"的连续两条本身就是干净的痕迹，删干净反而可疑。详见 `docs/DELIVERY-CHECKLIST.md` §九 ADR-1。
