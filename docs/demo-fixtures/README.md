## 四、唯一路径原则

- `notice.txt` 在**全仓只有一个路径**：`docs/demo-fixtures/notice.txt`。
- 仓库根 `fixtures/` 已删除，**不保留任何副本目录**；`npm run parse` 统一读 `docs/demo-fixtures/notice.txt`。
- 任何文档、脚本、测试只能引用该路径，**禁止复制第二份**。仓库里出现两份内容相同的文件，git 会存成两个独立 blob，clone 出来就是两份各自变旧的副本。
- 唯一性靠"只有一处"，不靠文件系统技巧。发现第二份副本，按 bug 处理。

## 五、时间政策（不可协商）

```
DEMO_NOW = 2026-10-19T09:00:00+08:00
```

- 解析、冲突检测、重排、单测、录像**全部**用它；代码禁止以 `Date.now()` / `new Date()` 作默认时钟。
- 录制日是 10-27，跑系统时间会让"这周六/下周一"整体错位一周（"这周六"算成 10-31，而原文那件事在 10-24），画面一眼假。证据见 EXPECTED 第六节。
- 换素材或换时钟 → EXPECTED 整表重算，不许只改几个数字。

## 六、换算规则（以 DEMO_NOW = 2026-10-19 周一为基准）

- 本周 = 10-19 ～ 10-25；下周 = 10-26 ～ 11-01；下下周 = 11-02 起
- 本周三 = 10-21；下周三 = 10-28；这周六 = 10-24；下周一 = 10-26；本月底 = 10-31
- 无具体时刻的截止 → 当日 `23:59`；`24:00` 归一化为次日 `00:00`
- **只给开始时间、未给结束 → 默认 90 分钟，并置 `needsReview: true`**（全项目统一）
- 相对词与文内明写日期冲突时：以**明写日期**为准，并置 `needsReview: true`
- 字段名只允许 `needsReview`；早期草案里的别名已弃用，任何别名按 bug 处理

## 七、导入 JSON 的字段契约（`demo-seed.json`）

```jsonc
{ "seedVersion": "v1", "demoNow": "2026-10-19T09:00:00+08:00", "tasks": [ /* 18 条 */ ],
  "expectedConflicts": [ /* 3 条 */ ], "expectedProposalTargets": { "A": {}, "B": {}, "C": {} } }
```

每条 Task：`id, title, date, start, end, durationMin, deadline, priority, location, locked, flexible, status, estateMin?`

- `locked: true`（seed 里 9 条）= 固定课/固定排班，**任何方案不得移动**；"固定课被挪 0 条"由它计算，非 0 即方案作废；
- `flexible: true` = 可顺延/可压缩，影响冲突降档与缓冲判定；
- `deadline` 非空且 `date` 为 `null` 的是纯截止任务，只参与规则 4。
- 解析输出（notice.txt 路径）同样必须产出 `locked`：本周只有 1 条 `locked`（`t_tutor_cls` 高数补课），志愿培训为 `flexible: true`；明细见 EXPECTED 第一节。15 条版的 4 条 `locked`（课表/兼职×2/体测）属于回归素材，别和这一条混。
