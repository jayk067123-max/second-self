# 待归档队列（QUEUE）

> 机制：**任何代码改动 = 一个待归档事件，10 分钟内建卡 + 建截图通道，不许拖到最后。**
> 维护人：Prompt官。谁都可以往这加行，只有 Prompt官能改状态。
> 状态只允许四种：`⏳待建卡` / `🟡已建卡·待素材` / `🟠素材齐·待对账` / `✅已归档`

## 触发源（三种，任一出现就在 10 分钟内开一行）

1. **git 提交出现**：`git log --oneline -1` 有新的、非 docs 提交 → 立即开行，查有没有对应 md；
2. **群里/私聊出现"改好了""跑通了"**：立刻开行，先把截图通道目录建出来；
3. **用户要下发新需求**：先开行并建卡，再让 AI 动工（**先卡后码**，不允许反过来）。

## 10 分钟动作清单（照做，不用想）

- [ ] 在 `docs/prompts/` 建/更新对应 `NNN-*.md`，填 §1 意图卡
- [ ] 在 `05-Prompt与演进记录/` 建同名素材目录（`NNN-<模块名>/`）
- [ ] 在群或私聊里提醒改动人：**本轮结束立刻截 4 张**（我的Prompt / AI首版 / 出错现场 / 修正后跑通）
- [ ] 盯 `git log --stat`：若改动文件数远超 md §3 描述 → 记一条「疑似一次性大提交」待查
- [ ] 本条状态推进，到点未推进就在群里点名

## 对账红线

- md 写"实现了 X"，提交里却查不到 X 的对应用文件 → 红灯
- 一个提交里出现超过 3 个不同模块的改动 → 红灯，立刻要求拆分叙述
- 素材目录空着但 md 状态写了"已归档" → 红灯
