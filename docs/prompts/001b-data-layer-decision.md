## 2. 指令原文（逐字）

> **归档注记**：以下原文一字未改。其中「没预编译包就要 node-gyp」的说法**该措辞已于 2026-10-18 在 `ARCHITECTURE.md` ADR-1 中精化**（预编译包实际存在，风险来自版本/平台不匹配时回退本地编译）。原文与精化版两段并存，详见 §4。

```text
依赖清单大体认可，但必须砍一刀：

砍掉 drizzle-orm + better-sqlite3，MVP 不做服务端数据库。三条理由：
1. better-sqlite3 是原生模块，评委机器上没预编译包就要 node-gyp + Visual Studio Build Tools，`npm i` 直接卡死——这是 10 分钟复现指南的头号杀手，比功能少一个严重得多。
2. B 的产品形态根本不需要服务端持久化：任务是本地的，浏览器 localStorage 足够，还能顺带讲"数据不出本机"的隐私卖点。
3. 少一个原生模块，装依赖快一倍，你最需要的两条验收命令（`npm ci`、`npm run dev`）在陌生机器上的成功率直接上一个台阶。
```

## 3. 这条指令解决了第一轮指令自身的一个矛盾（归档人观察）

001 §2 第一轮指令里，第 1 步已经明确要求「用 zustand + persist 存 localStorage」，但同一份指令认可的技术栈清单里仍列着 `drizzle-orm` / `better-sqlite3`。**两者并存意味着"本地存储"和"服务端数据库"同时存在**，数据到底落在哪、适配层还要不要，实现方无从判断。

第二轮这条指令把这个矛盾一次性砍掉了：不留服务端数据库，localStorage 是唯一持久化。所以它不是单纯的"砍功能"，是**消歧**。

> 这条观察标注为归档人判断，原始消息中未明说。写进技术文档时按"观察"表述，不要写成"人类当时就想到了"。

## 4. 措辞演进：两个版本都保留，不统一

同一件事，指令原文与后来的 ADR-1 措辞不同，**刻意都留着**：

| 版本 | 原文 | 精确度 |
|---|---|---|
| 指令原文（2026-10-18） | 「better-sqlite3 是原生模块，评委机器上**没预编译包**就要 node-gyp + Visual Studio Build Tools」 | 粗：把触发条件说成"没预编译包" |
| `ARCHITECTURE.md` ADR-1（第 162 行） | 「虽然有预编译包，但**预编译产物与 Node 版本、运行平台强绑定**，版本不匹配时会回退到本地编译，需要 node-gyp + VS Build Tools，在评委机器上就是一次不可控的失败」 | 准：预编译包存在，风险来自版本/平台不匹配 |

> **指令原文如此，后续在 ADR-1 中措辞更精确。** 不统一成漂亮的一致版本——人一开始说得粗、后来被事实修正、且修正痕迹留在文档里，这是最可信的演进证据；磨平了反而像事后编的。
