# 意图卡模板（TEMPLATE）

> 用途：**发 Prompt 之前**先填这张卡，再复制卡里的 Prompt 区块去问 AI。
> 目的：把「我想要什么」写死在纸面上，事后才拿得出证据证明结果不是 AI 自由发挥、也不是事后拼接。
> 用法：复制下面整段 → 另存为 `NNN-<模块名>.md` → 填完再发 Prompt → 交互结束后补 §5 和 §6。

---

## 复制区开始

```markdown
# NNN · <模块名>

- 日期：YYYY-MM-DD
- 阶段：<省赛预指导 / 省赛最终>
- AI 工具：<如 Claude Code / Cursor / DeepSeek / Copilot>，模型：<具体型号或版本>
- 对应提交：`<拟定的 commit message，含 [prompt:NNN]>`
- 关联文件：<本轮涉及/改动的源码文件路径>
- 记录性质：真实记录 / 补记（补记必须写明）

## 1. 意图卡（发 Prompt 前填）

| 项 | 内容 |
|---|---|
| **目标** | 一句话：这轮要拿到什么可运行、可验收的东西 |
| **上下文** | 我喂给 AI 的：①贴了哪些文件（列路径/贴了几段）②项目现状一句话 ③前置轮次编号 |
| **约束** | 技术栈 / 目录 / 命名 / 不许新增的依赖 / 性能或体量限制 |
| **禁止事项** | 明确不许 AI 做的事（如：不许改数据库结构、不许引入新库、不许动 X 文件、不许重写整个组件） |
| **验收标准** | 可执行的检查项，写完就照着点：①…②…③… |
| **本轮求助点** | 只要 AI 解决什么，不要它顺手做什么 |

## 2. 我的 Prompt（原文）

> 原样粘贴，不改错别字、不改语气。分多轮就按时间顺序编号贴全。

```text

```

```text

```

## 3. AI 的建议 / 产出（摘要 + 关键原文）

- 结论/方案：
- 改了哪些文件：
- 关键代码片段（贴最能说明问题的 10-30 行）：

## 4. 我如何引导与修正（**最重要的一节，不许空**）

按「现象 → 我的判断 → 我下的指令 → AI 的响应」记，至少 1 条，真实出过 bug 就记 bug：

| # | 现象（AI 写歪/报错/跑不通） | 我的判断 | 我下的指令（原文） | 结果 |
|---|---|---|---|---|
| 1 | | | | 已修正 / 部分修正 / 改为我手改 |

> 若本轮一次就对、没有任何修正，写「本轮无修正」并说明为什么一次到位（例如 Prompt 里已把接口签名写死）——不要为了凑内容编 bug。

## 5. 最终结果（可验证）

- 可运行的证据：<启动命令 + 看到的界面/输出 / 测试通过截图路径>
- 验收标准逐条对齐：①✅/❌ ②✅/❌ ③✅/❌
- 偏差说明：与意图卡不一致的地方，为什么接受

- 下次同类任务，Prompt 里应该提前写死什么：

## 7. 证据附件

- 截图/录屏目录：`05-Prompt与演进记录/NNN-<模块名>/`
- 附件清单：<文件名 1>、<文件名 2>
```

## 填写纪律（三条硬规矩）

1. **先卡后 Prompt**：意图卡 §1 必须在发 Prompt 之前写完。事后补的卡要在「记录性质」标注**补记**。
2. **原文不动**：§2 的 Prompt 不许润色。AI 答得烂也要留着，那才是过程。
3. **§4 不许空**：这是评委看「意图控制」维度唯一能落地的证据。整轮顺风顺水就写「本轮无修正 + 原因」。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把 Prompt 改通顺了再贴 | 一眼假，直接扣意图控制分 | 贴原话，错别字也留 |
| §4 写「AI 有 bug，我修复了」 | 无法证明是你引导的 | 写你具体说了什么、AI 之后改了什么 |
| 一轮塞 8 个需求 | 无法归因，无法复现 | 一个编号只做一件事 |
| 代码全写完才补文档 | 时间线对不上 git | 每轮结束立刻归档，与提交同批 |
