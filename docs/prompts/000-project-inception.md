# 000 · 项目启动与团队分工

- 时间：项目启动日
- 参与方：参赛者（本人，[组别已脱敏]）+ AI 团队
- 对应提交：`chore: 项目脚手架与协作规范`
- 记录方式：真实对话整理（非事后编造）

## 1. 我的 Prompt（意图）

把赛事全部规则原文交给 AI，并要求：

> 我报名的是 [组别已脱敏]。现在我们先确立选题，然后我筛选后再讨论整个项目的思路与框架。之后赛事要求上传 GitHub、提交 Prompt 记录等材料，每次我们完成后由其中一个 Bot 负责提交，另有写代码的 Bot，还有负责检查全部的 Bot，你都安排一下，安排好了我们就开始项目。

意图拆解：
1. 先定选题，由我（人类）筛选拍板。
2. 再定项目思路与框架。
3. 交付材料（GitHub 仓库、Prompt 记录、视频、文档）需要固定责任人和流程。
4. 不要 AI 替我做产品决策，AI 负责提供方案与执行。

## 2. AI 的产出（本轮）

AI 按赛事评分权重（可复现 25% / 解题 25% / 意图控制 20% / 工程质量 15% / UX 15%）拆出 7 个角色并建立分工与提交纪律：

- 选题官：候选选题、痛点、MVP 范围、高光镜头
- 全栈手：架构约束 + 代码实现
- Prompt官：意图控制策略 + Prompt 快照归档
- 交付官：全部 git 操作、快照索引核对、最终提交物清单
- 文档官：README 10 分钟复现指南 + ≤30 页 PDF 技术文档
- 映像官：UX 细节 + 5-8 分钟演示视频分镜
- 评委：按官方五维标准对抗式自检

并建立本仓库骨架：`.gitignore`、`.env.example`、`docs/prompts/`、`README.md`。

## 3. 我的引导与修正

- AI 首轮给出的分工包含"先搭骨架跑通再说"的选项，我明确否掉了——先定选题再写代码，避免返工。
- AI 提议由全栈手自行 commit，我要求「其中由一个 Bot 专门负责提交」，于是拆出独立的交付官，代码与提交分离。

## 4. 最终结果（可验证）

- 仓库初始化，首次提交为流程脚手架而非业务代码。
- 提交历史从第 0 轮即可追溯，避免"initial commit 即全部功能"的扣分项。

## 5. 经验沉淀

- 选题未定前不写业务代码；脚手架、规范、环境变量模板可以先落地。
- 每一个后续 Prompt 都按「意图卡：目标/上下文/约束/验收标准/禁止事项」结构记录。
