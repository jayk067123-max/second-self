## 0. 红线（不可协商，由主 Bot 拍板于 2026-10-18）

以下三条是本项目的硬约束，任何实现、文档、演示都必须遵守；违反即视为选题跑偏，需选题官与主 Bot 双签才能改。

**红线 1 · 判定与提议分离**
确定性代码负责"判+存"，大模型只负责"读+提议"；冲突判定、方案校验、回滚全在本地，断网可用。

**红线 2 · AI 只在三个明确动作后面**（v1.1：原 2 个，新增「解析这张图」）
AI 只出现在 `解析这段话`、`解析这张图`、`生成重排方案` 三个动作之后。**绝不提供聊天入口**，不做"跟 AI 聊着聊着就排好了"的形态。

**红线 3 · 数据入口只有三条**（v1.1：原 2 条，新增截图）
只有「粘贴文本」「截图（图片）」「手动新增」三条入口。无 OAuth、无账号体系、无云同步，数据全在浏览器本地。

> v1.1 这两处红线修订源于截图录入与完整性校验两条已落地（`28a6adf` / `12b384d`），按 §0 约定需「选题官 + 主 Bot」双签，**双签待补**；补签前以 `需求定义书` v1.1 为准执行。

## 3. 目标用户画像

### 人物小传

**林晓，福州某普通本科院校大二学生。**

- 这学期 6 门课，其中《数据结构》《大学物理》两门是硬骨头；
- 是学院一个 40 人社团的部长，负责每周活动通知与物资借用；
- 在准备蓝桥杯省赛（截止 11 月中），同时在跟一个大创项目；
- 周末在市区的培训机构兼职助教，排班表由机构微信群发；
- 不用电脑时基本在手机上，微信 300+ 未读，日历 App 装过三次、都弃了。

**她的一天，信息从这些地方流进来：**

1. 班级微信群 @全体成员 通知（改课、调课、交材料）
2. 社团微信群 + 接龙（活动时间反复改）
3. 教务系统课表（截图存在相册，学期中间改过一次教室没人通知）
4. 学习通 / 超星 / 雨课堂的作业 DDL 提醒（分散在三个 App）
5. 兼职机构的排班表（每周日晚上发、经常临时换班）
6. 竞赛群（通知、评审时间、线上答辩会议链接）
7. 自己的备忘录 + 便利贴 + B站/小红书收藏的"待看"

**她的现状**：手机日历手敲了三分之一就放弃；冲突全靠撞上才知道；计划被改一次，全盘作废，然后干脆不排了。

**典型时刻**：周日晚上 11 点，她想把下周排一遍，翻了 20 分钟微信，最后在备忘录写了五行字就睡了。

## 4. 真实痛点（3 条）

### 痛点 1：冲突永远在"撞上"那一刻才被发现

- **现在怎么凑合**：靠记忆比对，或者临出发前才想起两件事撞了，然后临时请假/放人鸽子。
- **为什么凑合不了**：冲突不是两件事同时刻才算——通勤、提前准备、连续满课后的体力，都是隐性冲突。人脑记不住 6 个维度的重叠，一学期要踩几十次。

### 痛点 2：排过一次的计划，一被打乱就彻底废弃

- **现在怎么凑合**：计划作废后直接放弃排期，改用"想起什么做什么"，靠焦虑驱动。
- **为什么凑合不了**：真实生活里每周至少有 2 次改期。只要重排成本高于收益，任何自制日程表都会在第二周死亡。缺的不是排期工具，是**改一次的时间成本**。

### 痛点 3：所有信息散在 7 个入口，没有任何一个视图是"我的一天"

- **现在怎么凑合**：微信群置顶 + 备忘录 + 日历 + 便利贴，四套并行，互相不知情。
- **为什么凑合不了**：置顶只解决"记得看"，不解决"排得开"。且通知是自然语言（"周四下午两点半改到实验楼 B305，记得带电脑"），没有工具能把它变成可计算的时间块。

## 5. 用户故事（按 P0 主线排序）

1. **As a** 同时上 6 门课、管社团、备竞赛的大二学生，**I want** 把一段乱糟糟的群通知**或一张课表截图**直接粘进去，它变成我能看懂、能改的时间块，**so that** 我不用手敲日历，也不会再漏掉改课和换班。
2. **As a** 计划总被打乱的学生，**I want** 系统主动把冲突画出来（重叠、来不及、当天超载），并给我 2–3 套重排方案对比，让我看清"挪了什么、代价是什么"，**so that** 我能在一分钟内决定，而不是花一小时重排。
3. **As a** 怕改错的学生，**I want** 接受方案后还能一键回滚、重传课表时旧数据被干净替换而不是叠加成一堆重复项，**so that** 我敢点"重排"、也敢再传一次新表，而不是怕把好好的计划弄坏。

## 6. 功能优先级

### P0 —— 10-31 前必须能演示（一条主线，缺一不可）

| # | 功能 | 验收标准 |
|---|---|---|
| P0-1 | 粘贴文本 → 任务结构化 | 粘贴 200 字以内的群通知/课表，产出含「标题/日期/起止/地点/优先级」的任务卡，字段错误可在卡片上直接改 |
| P0-2 | 手动新增任务 | 一个表单 10 秒内加一条任务（含时长、截止、优先级） |
| P0-3 | 冲突检测引擎（纯本地规则） | 检测 4 类冲突：时间重叠、缓冲不足（含通勤）、单日超载、DDL 前置准备不足；给出可解释文字 |
| P0-4 | 冲突可视化 | 周视图时间轴上用红色重叠带 + 冲突卡片列表，点卡片定位到时间轴对应位置 |
| P0-5 | 重排方案生成（2 套并排） | LLM 只输出"时间块 JSON 建议"，本地校验合法性；两套方案并排展示差异高亮（挪了哪几条、牺牲了什么） |
| P0-6 | 接受 + 回滚 | 接受后应用变更；顶部历史栈支持多步撤销/回滚，一键还原上一版 |
| P0-7 | 今日视图 + 极简几何分身 | 今日待办清单 + 几何形象（进度环 / 表情 / 呼吸动效）随完成度变化 |
| P0-8 | 本地持久化 | localStorage / IndexedDB，刷新不丢数据；全程无必须联网的第三方依赖 |
| P0-9 | 截图 → 任务（v1.1 新增） | 客户端压缩后上传；逐行成卡；**图片路径不显示覆盖率**（无可信原文可比对），但未识别处必须标黄可改 |
| P0-10 | 完整性校验（v1.1 新增） | 服务端用原文**逐行重算**归属，不采信模型自述；「没看懂，请你确认」逐行可补成任务或显式忽略 |
| P0-11 | 重传课表自动覆盖（v1.1 新增） | 重传时由用户显式选「覆盖哪一份」（默认上次同渠道的，指纹只算默认值）；改/删走原地 update，`done`/`locked` 不重置；覆盖前快照；摘要「新增/调走/删除/未变」四数；课程名不做同义合并 |
| P0-12 | 缺信息主动追问（v1.1 新增） | `needsReview` + `uncovered` 聚成**结构化提问，一屏一问**，随时可「剩下的我自己改」跳列表全览；作答只产 patch 并与修正表共用同一 store action；**不做自由对话** |

> **注意**：P0-1、P0-5、P0-9 是**唯一三处**调用大模型（文本解析 / 重排建议 / 图片解析）。判定（P0-3）、完整性重算（P0-10）与写回/回滚（P0-6）必须是确定性代码。这是本产品的架构主张，也是答辩要点。

## 7. P0 的"不做什么"清单

1. **不做聊天框**。不提供"跟 AI 聊着聊着就排好了"的对话界面。AI 只出现在三个按钮后面：`解析这段话`、`解析这张图`、`生成重排方案`。缺信息追问（P0-12）也必须走**结构化提问、一屏一问**，随时可"剩下的我自己改"跳列表全览，不做连问输入框。
2. **不让 AI 做判定**。冲突是不是存在、能不能接受、回滚到哪一步，全由本地确定性代码决定；LLM 只负责「抽取」和「建议」。
3. **不做 3D / 立绘分身**。分身只用几何图形 + 动效，任何需要美术资源的形象一律不做。
4. **不做日历 OAuth 接入**。数据入口只有两个：粘贴文本、手动新增。不连 Google / 苹果 / 手机系统日历。
5. **不做账号体系**。无登录、无云同步，数据全在浏览器本地（同时是隐私卖点）。
6. **不做拖拽式甘特图编辑**。P0 期间任务卡的编辑只走表单和"接受方案"，不投入自研拖拽引擎。
7. **不做多日连续场景**。P0 只保证「一周视图 + 今日视图」两种，不做月视图、不做学期视图。
8. **不做自动提醒/推送**。推送依赖系统能力，赛期内不碰。

## 8. 三个高光镜头（评委最容易记住的画面）

### 镜头 1：五秒成型
屏幕左侧是一段真实的、带错别字和口语的微信通知（"周四下午两点半那个课改到实验楼B305 记得带电脑"）。点击 `解析这段话` → 右侧任务卡像洗牌一样依次落下，每张卡上已经带好日期、起止、地点，未识别字段用黄色边框标出，用户一下就改好。
**记忆点**：乱文本 → 结构化卡片的一瞬间，动静对比强。

### 镜头 2：冲突被画出来
周视图上，两块时间像磁铁一样"啪"地叠在一起，重叠区域变红并轻微脉冲，下方冲突卡片同步亮起：`周三 14:00–15:40 与 社团例会重叠`。点击卡片，时间轴镜头平移到冲突处。
**记忆点**：把"看不见的冲突"变成"看得见的红色叠层"。

### 镜头 3：并排重排 + 一键回滚
点击 `帮我重排`，左右两套方案并排出现：左边"最小改动（只挪 2 条，周六早八牺牲）"，右边"最优休息（挪 5 条，周三空出整块）"。差异行有高亮和连线。选左 → 时间轴上的任务块像拼图一样平移归位，分身的表情从 😖 松开成 🙂。接着点 `回滚`，整条时间轴以倒放动效退回原状。
**记忆点**：方案对比 + 可回滚——这是"别人做不出来"的硬东西。

## 10. 风险清单

| 风险 | 具体表现 | 缓解方案 | 量化目标 |
|---|---|---|---|
| **数据来源风险** | 演示时用"编造的漂亮数据"，被质疑不真实 | 预置 3 份真实脱敏素材（群通知原文、课表截图转写、兼职排班）；演示用其中一份；提供"一键载入 Demo 数据" | 至少 1 份来自参赛者本人的真实通知 |
| **LLM 日期/时间解析失败** | "下周四""月底前""改到两点半"解析错，任务卡错位 | 三件套：① 结构化输出强约束（JSON schema + 失败重试）；② 低置信字段黄框高亮 + 人工改；③ 相对时间以"录入当日 + 明确锚点"注入 prompt | 干净文本 ≥95%；脏文本 ≥80%，其余全部落在人工纠错通道 |
| **LLM 重排幻觉** | 给出不合法方案（撞车、超时长、违背 DDL） | LLM 只产出建议 JSON → 本地校验器逐条验（不重叠、不超日容量、DDL 前置）；不过则丢弃该方案重试一次 | 校验不过的方案 0 次呈现给用户 |
| **动效性能** | 时间轴 + 分身动画掉帧，演示机卡顿 | 只用 transform/opacity；列表虚拟化；分身动画纯 CSS；开 `prefers-reduced-motion` 降级 | 演示机型 60fps，首屏 <1.5s |
| **范围蔓延** | 想做月视图、想接日历、想做立绘 | 本文件第 6、7 节即红线，任何新增功能需选题官 + 主 Bot 双签 | P0 之外零新增 |
| **"又一个日程 App"质疑** | 评委认为是套壳 | 答辩主叙述固定为「冲突可视化 + 方案对比 + 可回滚」三点，演示必走回滚 | 三点必须在视频中出现 |
